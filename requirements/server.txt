# ESWS application image — modern InVEST 3.20.0 geospatial stack + Django dashboard.
#
# A single image (docker/Dockerfile.invest) backs every Python service: the pywps
# server, the file server, and the Django dashboard. The dashboard's views import
# tools/easyows.py (GeoServer client), so it needs the same geo stack as the WPS
# server — unifying on one image avoids duplicating GDAL/GeoServer deps.
#
# NOTE: GDAL (and its Python bindings) are installed from conda-forge in
#       docker/Dockerfile.invest. Do NOT add gdal here.
#
# Supersedes the InVEST 3.8.0 / Django 2.2 era pins in ../requirements_py3.txt.

# --- InVEST + geoprocessing ---
# No Linux wheels are published for natcap.invest, so this builds from sdist
# against the conda-forge GDAL; 3.20.0 requires gdal==3.10.*, which is why the
# Dockerfile pins that exact series.
natcap.invest==3.20.1
pygeoprocessing>=2.4.11
# tools/crs_identify.py depends on this directly: it is what recognises a CRS
# GeoServer cannot name. It was only ever present by way of geopandas, which
# natcap.invest pulls in and could stop pulling in -- and publishing breaks
# quietly when it goes, because a layer with no identified CRS is published
# disabled rather than refused.
pyproj>=3.7.2
taskgraph[niced_processes]>=0.11.2
pint
Babel

# --- WPS middleware ---
pywps>=4.7.0,<4.8
Flask
flask-cors

# --- GeoServer REST client ---
# Python 3 maintained fork of gsconfig; provides the `geoserver` package that
# tools/easyows.py imports (geoserver.catalog.Catalog). Replaces the old
# boundlessgeo/gsconfig git pin.
geoserver-restconfig

# --- Django dashboard (tools/wpsclient) ---
# 6.1, the current release, on Python >= 3.12 which the image now has.
#
# This deliberately leaves the LTS track, so the trade is worth stating: 5.2 is
# an LTS supported to April 2028, while 6.1 is a feature release with roughly a
# 16-month window. Chosen over 6.0 because if you are leaving LTS anyway, the
# newer release buys the longer runway for the same compatibility risk. The next
# LTS is 6.2 (April 2027) and is the natural next stop.
#
# tools/wpsclient/requirements_py3.txt pins this too and must move with it --
# see the comment there for what silently breaks when it does not.
Django==6.1.*
django-extensions
owslib
beautifulsoup4

# --- misc used by easyows / handlers / views ---
requests
